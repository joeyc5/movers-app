# MC CRM reskin: local-model handoff brief

movers-app becomes MC CRM, one product under the MovingCommand SaaS umbrella.
Brand tokens live in `~/movingcommand-web/design-system/tokens.json`.

## What the local model does not do

Layout, hierarchy, density, and information architecture are design decisions.
Those come from the intent -> frontend-design -> impeccable pass and are fixed
before any task below starts. The local model executes against a decided
contract. If a task requires choosing how a screen should be organized, it is
the wrong task for this model.

## State of the codebase

- 16 pages, all on shadcn semantic tokens. 1 hex, 9 `text-[N]`, 24 `[Npx]` total.
- Three theme presets exist in `src/styles/presets/`. Adding a fourth is the
  whole color rebrand.
- `src/lib/preferences/theme.ts` is generated by `npm run generate:presets`,
  which scans the preset directory for `label:` and `value:` header comments.
- The login screen is unmodified starter template: command-key mark, "Hello
  again", "Login to continue".

## Constraints block

Paste this verbatim at the top of every task.

```
Repo: ~/movers-app. Next.js 16, React 19, TypeScript strict, Tailwind v4, shadcn.

Rules:
- Never modify anything in src/components/ui/ or src/components/calendar/.
  Style at the call site instead.
- Raw color values are legal ONLY in src/styles/presets/movingcommand.css.
  In any screen or component, use semantic tokens: bg-primary, text-muted-foreground,
  border-border. No hex, no rgb, no oklch, no text-[16px], no [24px].
- Do not add dependencies.
- Edit exactly one file per task, at the path I give you. Do not touch others.
- Biome: double quotes, semicolons, two-space indent, 120 char lines.
- Output the complete file, not a diff or a fragment.
```

After every task, run `npm run check:fix`. It is a free deterministic gate on
format and lint drift, and it catches most of what a small model gets wrong.

## Task A: the MovingCommand preset

One file: `src/styles/presets/movingcommand.css`. Copy the shape of
`tangerine.css` exactly, including the `label:` / `value:` header comment, and
replace the values with MovingCommand tokens.

Trap: MC tokens are hex, the presets here are oklch. Do not let the model
convert by hand, it will drift. Have it write a throwaway node script using a
color library to do the conversion, print the oklch values, then paste those in.

Then `npm run generate:presets` and set movingcommand as the default preset.

Verify: the app renders in MovingCommand blue with light and dark both legible.
Measure contrast, do not eyeball it.

## Task B: strip the template artifacts

Inventory first, deterministically:

```
grep -rn "Hello again" src
grep -rn "Login to continue" src
grep -rn "movers-app\|Movers App" src
```

Then one file per task, replacing the command-key mark with the MovingCommand
lockup and the template copy with real copy. Run the copy past stop-slop before
it lands. This is a small, bounded, mechanical job and it is the single highest
visible return in the repo.

## Task C: per-screen token cleanup

Feed it the grep output, not the codebase:

```
grep -rn "text-\[[0-9]\|\[[0-9]*px\]\|#[0-9a-fA-F]\{6\}" src/app src/components | grep -v src/components/ui/
```

One file per task. For each hit, the model either maps it to the nearest
existing token or flags it as needing a new token. It does not invent tokens.
You decide on the flagged ones.

Order: Clients first. AGENTS.md names it the most complete reference screen, so
whatever pattern lands there sets the standard for the rest.

Set context to at least 16k in LM Studio. Feed one file plus the constraints
