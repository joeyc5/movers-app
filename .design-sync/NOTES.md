# design-sync notes for movers-app

Repo-specific facts a future sync needs. Read this before touching anything in
`.design-sync/`.

## What this repo is

`movers-app` is a Next.js application, not a published design-system package.
The design system is the shadcn component library under `src/components`
(64 root components, 279 sub-parts) plus the Tailwind v4 token layer in
`src/app/globals.css`. The converter's `package` shape handles it, but three
things had to be built that a normal DS package ships on its own.

## The three generated inputs

Run these in order after adding, removing, or renaming a component:

```bash
node_modules/.bin/tsc -p .design-sync/dts-tsconfig.json      # 1. declarations -> dist/
node .design-sync/gen.mjs                                    # 2. entry, docs, exclusions
.ds-sync/node_modules/.bin/tailwindcss \                     # 3. compiled CSS
  -i .design-sync/tw-entry.css -o .design-sync/.cache/tailwind.css
```

1. **`dist/` declarations.** There is no build, so `tsc --emitDeclarationOnly`
   writes a `.d.ts` tree the converter reads for prop extraction.
   `package.json` carries `"types": "./dist/index.d.ts"` so `findTypesRoot`
   lands on it. Without this the emitted contracts collapse to
   `{ [key: string]: unknown }` and the design agent gets no API at all.
   `dist/` is gitignored and must be regenerated on a fresh clone.
2. **`gen.mjs`.** Writes `.design-sync/entry.ts` (the bundle entry barrel),
   `dist/index.d.ts`, the `componentSrcMap` exclusions, and one doc per root
   component into `.design-sync/docs/`. The group table and the four
   non-obvious root exports (`ChartContainer`, `DirectionProvider`,
   `ResizablePanelGroup`, `Toaster`) live at the top of the script. It fails
   loudly when a new module has no group, which is the intended prompt to add
   one.
3. **Compiled Tailwind.** `cfg.cssEntry` cannot point at `src/app/globals.css`:
   that file is Tailwind *source*, its `@import "tailwindcss"` is not a file on
   disk, and it contains zero utility classes. `.design-sync/tw-entry.css`
   imports it and adds explicit `@source` globs (v4 resolves those relative to
   the CSS file, so a file under `.design-sync/` scans nothing by default).
   **Recompile after editing any preview** — preview layout glue introduces
   utilities that were not in the repo when the last snapshot was taken.
   Verify a compile with `node .design-sync/.cache/check-vocab.mjs`, or by
   hand with two greps: `.bg-primary {` (a utility) and `--primary:` (a token).
   Both present means real CSS.

   The bottom of `tw-entry.css` is a deliberate `@source inline(...)`
   safelist. Scanning the repo alone yields only the utilities this product
   already uses, and the design agent writes its own layout markup: without
   the safelist its `gap-6`, `grid-cols-3`, and `divide-border` resolve to
   nothing and the design ships unstyled. The safelist is what takes the
   compiled sheet from 281 KB to 376 KB. Extend it when the conventions header
   promises a family it does not cover.

## Sub-parts are excluded as cards, on purpose

`componentSrcMap` nulls 279 sub-part exports (`DialogContent`, `CardHeader`,
`TableRow`, …). They stay in the bundle — the entry barrel exports every
module, so `window.MoversCRM.DialogContent` works — and each root's
`## Parts` section names them. Without the exclusion the design pane is 279
"preview not yet authored" floor cards against 64 real ones. The list is
generated by `gen.mjs`; never hand-edit it.

## cfg.storyImports.shim is load-bearing

The converter's rule-2 shim matches an import by *file name* against the
exported component names. shadcn files are kebab-case (`button.tsx` vs
`Button`), so nothing matched and every preview bundled a second copy of the
library from source: 130 KB per preview, ~45 s each, and separate React
context identities from the shipped bundle. `"storyImports": {"shim":
["/src/components/"]}` forces those modules to `window.MoversCRM`. Preview
bundles dropped to 5-11 KB. If preview sizes jump back over 100 KB, this
setting stopped matching.

## Fonts

The app loads 18 Google fonts through `next/font` and switches between them
with `html[data-font="…"]`. The default is Geist, via
`--font-sans: var(--font-geist)`. The bundle ships Geist Sans and Geist Mono
itself: the woff2 files are copied from the `geist` package into
`.design-sync/fonts/`, `@font-face` rules live in `.design-sync/fonts.css`
(wired through `cfg.extraFonts`), and `--font-geist` / `--font-geist-mono` are
defined at the bottom of `tw-entry.css`. The other 17 families are runtime
app chrome and are deliberately not shipped.

## Environment

- `npm install` inside `.ds-sync/` needs `--cache "$TMPDIR/npm-cache-ds"`.
  The default `~/.npm/_cacache` is outside the sandbox write allowlist and
  fails with EPERM, which a piped `| tail` will hide behind exit code 0.
- `package-validate.mjs` binds a local HTTP port for the render check, so it
  needs the Bash sandbox disabled. Sandboxed it dies on `listen EPERM`.
- Playwright and Chromium live in `.ds-sync/node_modules` and
  `~/Library/Caches/ms-playwright` (playwright 1.63.0 pins chromium 1243).
- A full build takes 45-60 minutes, almost all of it compiling 64 preview
  bundles (esbuild re-parses the lucide-react barrel per entry). For preview
  edits use `node .ds-sync/lib/preview-rebuild.mjs --components A,B,C`
  instead of a full rebuild.
- Never create `node_modules/movers-crm` as a self-symlink. It makes
  `PKG_DIR` a symlinked path, `isOwnProp` prefix-matching fails against the
  realpath'd `dist/` files, and every prop body comes out empty.

## Known render warns

Triaged and expected. A warn that is not on this list is new.

- **`[TOKENS_MISSING]`, 21 properties.** `--available-width` and
  `--available-height` are set by Radix at runtime. `--fc-event-color` and
  `--fc-event-contrast-color` come from FullCalendar. `--tw` is a Tailwind
  internal. The `--font-inter`, `--font-noto-sans`, and the other 15 family
  variables belong to the runtime font switcher (`html[data-font="…"]`), which
  the bundle deliberately does not ship. None of them affect the default
  render.
- **`EventCalendarViews` ships the floor card, and that is settled.** It has
  no file in `.design-sync/previews/`. FullCalendar's plugin classes and the
  copy of core compiled into `_ds_bundle.js` are separate module instances, so
  a preview that imports `dayGridPlugin` itself throws
  `Class constructor DayGridView cannot be invoked without 'new'`. Two routes
  were tried and both are dead: `cfg.overrides.EventCalendarViews.skip` on the
  only story leaves the card with nothing to render, which fails `[RENDER]`
  harder than the error did; and `cfg.extraEntries` pointing at a repo module
  that re-exports the plugins cannot be spelled at all, because the existence
  check resolves the path against the package root while esbuild resolves the
  same string against `ds-bundle/`, and no single value satisfies both. The
  component is fully importable, and its doc carries working usage code with
  the plugin requirement spelled out. Do not spend another build on this.
- **`ChartContainer` ships the floor card too.** Same dual-instance problem as
  the calendar: `ResponsiveContainer` only recognizes chart children from its
  own Recharts instance, and a preview importing `BarChart` from `recharts`
  gets a second copy and draws an empty box with no error. `cfg.extraEntries:
  ["recharts"]` is the documented fix and it does merge the exports, but it
  also wedged esbuild — the bundle step stopped making progress at 0% CPU
  across three clean restarts. Backed out. The doc carries the full working
  chart example.
- **`ContextMenu` shows only its trigger.** A right-click cannot be simulated
  in a static render, so the card shows the drop zone and the menu content
  stays closed. That is the honest state, not a break.
- **Thirteen components use `cardMode: "single"`.** Portals and fixed
  positioning escape a grid cell. `cfg.overrides` names each one with the
  story that represents it.

## Re-sync risks

- **`dist/` and the compiled CSS are gitignored.** A fresh clone has neither.
  Run the three commands above before the converter, or the run silently
  produces stub contracts and unstyled components.
- **The group table in `gen.mjs` is hand-maintained.** A new component module
  fails the generator until someone assigns it a group. That is deliberate.
- **Preview content is hand-written and can drift.** The docs embed each
  preview file verbatim as its `## Examples`, so a preview that stops matching
  the component's real API teaches the design agent the wrong thing. The
  render check catches crashes, not staleness.
- **`package.json` carries a `"types"` field that only design-sync uses.**
  Nothing imports `movers-crm` by name, so it is inert for the app, but it
  points at a gitignored path.
- **Only Geist is verified.** If the product's default font ever changes away
  from Geist, `tw-entry.css` and `fonts.css` both need updating or every
  design renders in a fallback face.
